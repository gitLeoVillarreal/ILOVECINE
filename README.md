# I LOVE CINE

#### Description:

This is my CS50x Final Project: "I LOVE CINE"
It's a movie web app where you can create an account, get recommendations from a movie that you liked, or play a guessing game using the posters of random movies while keeping track of your highest score.

#### Requirements

- TMDB API key (https://www.themoviedb.org/)
- Python libraries (Flask, sqlite3, dotenv, json, argon2-cffi)

#### Structure

My web app is designed with HTML and CSS and also has a backend with Python's library Flask. The project uses a python file called helpers.py where you generate a massive database in sqlite3 where you store the movies in a table called **movies** calling the TMDB API, you can manage how many movies you will save with a variable that stores the number of pages you want to loop, approx every page has like 20 movies, I used it with 100 pages that stores like 1600 movies depends on the filters you use. Also, I saved the genres in another table called **genres**, where I manage the names of them because the movies only have genres stored by IDs. On top of that, helpers.py also creates a **users** table so people can register an account, log in, and keep a persistent high score across sessions. All the requests are made on helpers.py so in app.py you manage the movies through the database.

#### Files

- `app.py`: Flask application with all the routes (`/`, `/login`, `/register`, `/logout`, `/home`, `/recomendations`, `/guessthemovie`) and the logic that queries the database.
- `helpers.py`: Collects movie and genre data from the TMDB API, builds the SQLite database (movies, genres and users tables), and handles score persistence.
- `requirements.txt`: Python dependencies needed to run the project.
- `ILoveCineDB.db`: SQLite database generated by helpers.py. Not included in the repository (or included as a starting point) — run `MovieDataBase()`, `GenreDataBase()` and `UsersDataBase()` from helpers.py to generate it locally.
- `.env` / `.flaskenv`: Environment variables, including the TMDB API key and the Flask `SECRET_KEY` used to sign sessions (not committed to version control).
- `templates/layout.html`: Base template with the shared page structure and navigation.
- `templates/home.html`: Landing page with a random selection of movie posters.
- `templates/login.html`: Login form for existing users.
- `templates/register.html`: Registration form for new users.
- `templates/recommend.html`: Form to input a movie title and displays the recommended movies table.
- `templates/guess.html`: Poster-guessing game interface with the blur effect and scoring logic.
- `static/styles.css`: Styling for all pages.
- `static/favicon.ico`, `static/favicon-16x16.png`, `static/favicon-512x512.png`: Site favicons.

##### helpers.py

Here is all the movie's info collection, plus the database connection and user-score helpers. In this file you will find two constant variables: **LEN** and **MAX_PAGE**. You can change it if you want to. The three functions needed at **main()** are **MovieDataBase()**, **GenreDataBase()** and **UsersDataBase()**, which together create every table the app needs. Functions:

- `Connection()`: Opens a SQLite connection to `ILoveCineDB.db` with `row_factory = sqlite3.Row` so query results can be accessed by column name.
- `MovieList()`: This function returns a list with all the movie's info requested in a json format that will be used like a python dictionary to be sorted by popularity.
- `LookupPoster(poster)`: Check if there is a poster. If it's true, then return the poster_url to use as an image. If not, the function will return a "Not Found" string.
- `MovieDataBase()`: This function creates the table **movies** and calls the function **MovieList()**. It will insert every movie in the MovieList result via SQL query with the help of a loop. Every movie stores its genres as a comma-separated list of genre IDs, which is why the genres table is used to resolve them into names.
- `GenreList()`: This function returns a list with all the genre info requested in a json format that will be used like a python dictionary.
- `GenreDataBase()`: This function creates the table **genres** and calls the function **GenreList()**. It will insert every genre in the GenreList result via SQL query with the help of a loop.
- `UsersDataBase()`: Creates the **users** table (`id`, `username`, `hash`, `max_score`) used for authentication and score persistence.
- `recommendation(movie)`: Looks up a movie's TMDB id by title, requests its recommendations from the TMDB API, and returns the matching rows from the local **movies** table.
- `random_poster_movie(cursor)`: Picks a random movie from the database and returns its id, title and poster URL, used both on the home page and in the guessing game.
- `get_max_score(userID)` / `set_max_score(userID, newMaxScore)`: Read and update a logged-in user's `max_score` in the **users** table, so their best score persists between sessions.

Also, here is the database schema I used for the tables:

```sql
CREATE TABLE movies (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    movie_id INTEGER NOT NULL UNIQUE,
    title TEXT NOT NULL,
    poster_url TEXT NOT NULL,
    genre_ids TEXT NOT NULL,
    popularity NUMERIC NOT NULL,
    rating NUMERIC NOT NULL,
    release_date DATE NOT NULL
);

CREATE TABLE genres (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    genre_id INTEGER NOT NULL UNIQUE,
    name TEXT NOT NULL
);

CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL,
    hash TEXT NOT NULL,
    max_score INTEGER NOT NULL DEFAULT 0
);
```

##### app.py

Here you'll find the app's routes:

- `/`: Redirects straight to `/home`.
- `/login`: Renders **login.html** and, on POST, verifies the submitted username/password against the **users** table using `argon2`'s `PasswordHasher`. On success it stores `user_id` and `username` in the session and redirects to `/home`.
- `/register`: Renders **register.html** and, on POST, hashes the password with argon2 and inserts a new row into **users**. Rejects the submission if the username is already taken or the password/confirmation don't match.
- `/logout`: Clears the session and redirects to `/login`.
- `/home`: Renders **home.html** with a set of random movie posters pulled from the database via `random_poster_movie`.
- `/recomendations`: Renders **recommend.html**, a form with one input and one button. The user enters the title of a movie they like, and on POST the app calls `recommendation("movie_title")`, which looks up the movie's TMDB id in the **movies** table and requests recommendations from the TMDB API. Those results are resolved against the **genres** table and rendered back as a table.
- `/guessthemovie`: Renders **guess.html**, a poster-guessing game with 5 tries. Every incorrect try costs progressively more points (10, 20, 30, 40 points), and a correct guess is worth 100 points. If the player is logged in, their best score is read from and written to the **users** table via `get_max_score`/`set_max_score`, so it persists across sessions; guests get a session-only high score that resets when the session ends.

##### guess.html

The poster's blur level is driven entirely by the server: every time a guess fails, `app.py` recalculates `guesses` and passes it back into the template through the `randomPoster` dict, so the hidden `guesses` input always reflects the current try count. On the JS side, `GuessMovie()` reads that value and calls `revealPoster(clicks)` to set the CSS blur filter accordingly. Originally `GuessMovie()` only ran on the search input's `onclick`, so the blur update lagged one click behind the actual guess count shown on screen. It now also runs once as soon as the script loads, so the poster's blur matches the current `guesses` value immediately on page load, not just after the user clicks the input again.

#### How to use it

To use my app, you need to get an API key from TMDB. You only have to log [here](https://www.themoviedb.org/) in and select the developer usage for the API key, then go to helpers.py and run **MovieDataBase()**, **GenreDataBase()** and **UsersDataBase()** that will create the database tables. Then set a `SECRET_KEY` in your `.env`/`.flaskenv`, run "flask run" in your terminal, register an account (or just play as a guest) and feel free to use it.
